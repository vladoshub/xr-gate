# Emulation controller: управление наклоном кисти, профиль v3

Режим включён по умолчанию. Он заменяет старые жесты на выбранных руках и
сохраняет физический ввод `override_controller`; положение и ориентация
контроллера проходят прежний путь. Сам алгоритм старых жестов, драйверы
SteamVR/Monado и протоколы SHM/TCP не меняются.

Существующая настройка `OVERRIDE_CONTROLLER_BLOCK_GESTURES_WHILE_STREAM_PRESENT`
теперь блокирует и новые жесты. В стандартном режиме запуска
`CONTROLLER_INPUT_MODE=controller_buttons_runtime_only` она по умолчанию равна `1`:
пока поток `override_controller` свежий, работают физические кнопки, а все жесты
эмуляции, включая D-pad и двуручный Menu, отключены. Это верно и для потока с
нулевыми кнопками. После последнего свежего кадра блокировка сохраняется ещё
`OVERRIDE_CONTROLLER_GESTURE_BLOCK_LATCH_MS` (по умолчанию 2000 мс).
Старые жесты на выбранных руках остаются отключены и после снятия блокировки.

При значении `0` новые жесты могут работать одновременно с контроллером:

```bash
EMULATION_CONTROLLER=1 OVERRIDE_CONTROLLER_BLOCK_GESTURES_WHILE_STREAM_PRESENT=0 \
  ./run_xr_client.sh --config xreal_ultra
```

У бинарника та же настройка называется
`--override-controller-block-gestures-while-stream-present 0|1`, задержка —
`--override-controller-gesture-block-latch-ms`. В режиме `hand_plus_controller`
совместная работа сохраняется независимо от этой настройки, как и прежде.

Когда совместная работа разрешена, физические кнопки объединяются с новыми
жестами. Trigger/grip получают большее из двух значений; если кнопку держат
оба источника, она отпускается после
отпускания обоих. Физический стик/панель при движении, касании или нажатии имеет
приоритет над наклоном кисти на обеих осях и направлениях D-pad. Касание центра
панели даёт нулевые оси. Когда физическая панель не используется, доступны оси
от кисти.

Правила исключения A/B/клика и двуручного Menu относятся к новым жестам.
Физические кнопки, включая Menu, продолжают работать без этих поз и при потере
видимости руки. При потере или устаревании потока контроллера его кнопки
отпускаются; свежие жесты руки доступны после окончания блокировки. Счётчики
сохраняют короткие физические нажатия между кадрами без повторов от одного удержания.

## Назначения

| Поза | Действие |
| --- | --- |
| Большой палец отогнут от ладони | Включён D-pad; направление задаёт наклон **самой кисти** |
| Большой прижат к ладони | Оси = 0, D-pad отпущен |
| Указательный разогнут, средний и безымянный согнуты | Trigger |
| Мизинец разогнут, средний и безымянный согнуты | Grip |
| Указательный и мизинец разогнуты, средний и безымянный согнуты | Trigger + grip |
| Кольцо большим и указательным, остальные три согнуты (1235) | A |
| Кольцо большим и указательным, остальные три прямые (1234) | B |
| V: указательный и средний прямые, безымянный и мизинец согнуты; положение большого любое | Thumbstick click, как физическое нажатие панели GearVR |
| **Обе руки** одновременно раскрыты, все пальцы прямые, большие отогнуты (1244) | Одна кнопка Menu |

D-pad, trigger и grip независимы и могут работать все вместе. Отдельное движение
большого пальца меняет только включение D-pad: его направление не двигает оси.
Наклон вычисляется по мировой вертикали в системе ладони (runtime использует Y вверх).
Разворот вокруг вертикали не меняет оси. Калибровка сохраняет отдельные направления
влево/вправо/вперёд/назад и мёртвую зону по разбросу нейтральных поз. Это устраняет
зависимость центра от первой раскрытой ладони и переходы углов через ±180°.
Система ладони строится из запястья и оснований пальцев, а не из кончика большого.
Большой палец, прижатый к ладони, выключает только перемещение, сохраняя trigger/grip.

A, B и клик панели имеют приоритет над обычными каналами этой руки: в этих позах
trigger/grip и перемещение отключены. Короткие переходные положения отфильтрованы
подтверждением позы. После A/B/клика верни четыре пальца в согнутую нейтраль
и разомкни кольцо: это предотвращает выстрел или захват при выходе из жеста.
Большой палец в нейтрали может быть поднят или прижат.
Для V раздвигать пальцы необязательно: распознаются два прямых пальца и два
согнутых. Старый жест с тремя прямыми пальцами больше не нажимает панель.
Прямой переход между подтверждёнными A и B разрешён; trigger/grip при нём
остаются выключены до согнутой нейтрали. Касание большого/указательного в
плотном кулаке само по себе не считается кольцом.

Для Menu нужны две достоверно отслеживаемые раскрытые руки одновременно на
протяжении `menu_hold_ms` (350 мс по умолчанию). Одна раскрытая рука Menu не
нажимает. Во время двуручного жеста остальные действия обеих рук отключены.
Menu публикуется один раз как нажатие на левой стороне и удерживается, пока
обе руки показывают жест; счётчики не создают повторных нажатий. Когда жест
закончится, верни руки в согнутую нейтраль перед обычным управлением.
Это обычный Menu, а не System/Home. Одноручных Menu/Home в новой схеме нет.
Чтобы двуручный Menu работал, эмуляция должна быть включена для обеих рук.

На левой руке A/B также доступны как X/Y при стандартной настройке алиасов
драйвера. Клик панели выдаёт тот же `thumbstick_click`, который назначен на
физический `BTN_LEFT` GearVR в стандартном профиле `empty_gearvr.json`.
Драйвер отображает его в joystick click и trackpad click.

## Обновление

Исправление по записи `gestures13` накладывается поверх v2 и `override-fix`:

```bash
git apply --check "$HOME/Downloads/xr-gate-emulation-controller-gestures13.patch"
git apply "$HOME/Downloads/xr-gate-emulation-controller-gestures13.patch"
```

Исправление совместной работы с `override_controller` накладывается поверх v2:

```bash
git apply --check "$HOME/Downloads/xr-gate-emulation-controller-override-fix.patch"
git apply "$HOME/Downloads/xr-gate-emulation-controller-override-fix.patch"
```

Этот вариант заменяет схему предыдущих двух патчей. Обновляющий файл
`xr-gate-emulation-controller-v2.patch` накладывается **после них** в корне
исходников:

```bash
git apply --check "$HOME/Downloads/xr-gate-emulation-controller-v2.patch"
git apply "$HOME/Downloads/xr-gate-emulation-controller-v2.patch"
```

Используй новый `runtime_adapters/xr_runtime_adapter/configs/emulation_controller.json`
с `version: 3`. Калиброванные профили версий 1/2 отклоняются: прежний признак
наклона несовместим с новой калибровкой. Профиль v2 без сохранённой калибровки
принимается для простых переключателей; для новых геометрических порогов
используй файл v3. Калибровка измеряет отдельные направления каждой руки.
Старые `finger_mode`, `thumb_mode`, `wrist_weight`, счёт 2/3/4 согнутых пальцев
и отдельные назначения щипка для сторон удалены из этой схемы.

Собрать адаптер и инструмент калибровки из исходников:

```bash
sudo apt-get install cmake g++ libcli11-dev nlohmann-json3-dev
ROOT_PROJECT="$PWD" BUILD_JOBS=2 \
  bash runtime_adapters/xr_runtime_adapter/scripts/linux/install_xr_runtime_adapter.sh
```

Обновление уже распакованного релиза из каталога исходников, с заменой пути на свой:

```bash
ROOT_PROJECT="$PWD" BUILD_JOBS=2 \
  INSTALL_BIN_DIR="$HOME/xr-gate-release/xr-gate/bin/runtime_adapters/xr_runtime_adapter" \
  INSTALL_SCRIPT_DIR="$HOME/xr-gate-release/xr-gate/bin/scripts/runtime_adapters/xr_runtime_adapter" \
  bash runtime_adapters/xr_runtime_adapter/scripts/linux/install_xr_runtime_adapter.sh
```

Basalt, Mercury и драйверы SteamVR/Monado пересобирать для этого обновления не нужно.

## Запуск

Из каталога распакованного релиза:

```bash
EMULATION_CONTROLLER=1 RUNTIME_APP_TCP=1 \
  ./run_xr_client.sh --config xreal_ultra
```

Сначала держи кисть в удобной центральной ориентации: четыре пальца согнуты,
большой отогнут. Без сохранённой калибровки первая такая видимая ориентация задаёт
центр наклона на запуск; раскрытая ладонь его не захватывает.
Дальше управляй наклоном кисти. При потере руки кнопки отпускаются; при восстановлении
обычная нейтраль сохраняется. После сброса источника/координат центр захватывается заново.

С сохранённой калибровкой центр берётся из профиля, и движение доступно уже
при первом появлении руки с разогнутым указательным или мизинцем. Сначала
показывать кулак для захвата центра требуется только автоматическому профилю.

Для собственного профиля передай абсолютный путь к JSON версии 3:

```bash
EMULATION_CONTROLLER=1 \
  EMULATION_CONTROLLER_CONFIG="$HOME/emulation-v3.json" \
  RUNTIME_APP_TCP=1 \
  ./run_xr_client.sh --config xreal_ultra
```

Эмуляция включена по умолчанию. Для исходных grab/pinch-жестов задай
`SIMPLE_GESTURES=1` и перезапусти трекинг. Прямой бинарник принимает
`--simple-gestures`, `--emulation-controller 0|1` и `--emulation-controller-config PATH`.

## Настройки v3

| Параметр | Назначение |
| --- | --- |
| `left.enabled`, `right.enabled` | Включить эмуляцию для выбранной руки; другая сохраняет прежний ввод |
| `left.invert_x/y`, `right.invert_x/y` | Инверсия осей эмуляции; физические оси не меняются |
| `left.deadzone`, `right.deadzone` | Мёртвая зона конкретной руки; калибратор оценивает её по нейтрали |
| `range_degrees: 30` | Наклон до полного отклонения в автоматическом профиле |
| `deadzone: 0.18` | Мёртвая зона осей |
| `smoothing_ms: 40` | Сглаживание осей; 0 отключает |
| `dpad_mode: "four_way"` | 4 направления; `eight_way` разрешает диагонали; `off` оставляет только аналоговые оси |
| `thumb_enable_clearance: 0.85`, `thumb_disable_clearance: 0.80` | Разные пороги поднятого/прижатого большого пальца |
| `thumb_extension_on: 0.86`, `thumb_extension_off: 0.80` | Дополнительная проверка распрямления большого пальца |
| `extension_on: 0.7`, `extension_off: 0.45` | Пороги разгибания, используются для trigger/grip и поз |
| `little_extension_on: 0.60`, `little_extension_off: 0.45` | Отдельные пороги мизинца; облегчают включение Grip при небольшом остаточном сгибе |
| `curl_on: 0.65`, `curl_off: 0.45` | Пороги согнутого положения |
| `button_confirm_ms: 45` | Подтверждение разгибания указательного/мизинца по новым оптическим кадрам |
| `pose_confirm_ms: 120` | Подтверждение A/B/клика панели |
| `menu_hold_ms: 350` | Удержание двуручного Menu |
| `pinch_on_ratio: 0.30`, `pinch_off_ratio: 0.50` | Соединение/разведение кончиков большого и указательного, нормализованное на ширину ладони |
| `min_confidence: 0.3`, `max_age_ms: 120` | Достоверность суставов и предел возраста оптического кадра |

`thumb_clearance` — расстояние от кончика большого пальца до основания
указательного пальца, делённое на ширину ладони. Это геометрический
признак позы, а не измерение давления. Увеличение обоих его порогов раньше
отключает D-pad при приближении большого пальца к ладони.
Дополнительно `thumb_straightness` сравнивает расстояние между началом и концом
большого пальца с длиной его суставной цепочки: согнутый большой не активирует
оси только из-за того, что его основание находится далеко от центра ладони.

## Запись и калибровка

Для русских подсказок с автоматическим таймером и ZIP-записью:

```bash
python3 runtime_adapters/xr_runtime_adapter/tools/xr_gate_gesture_debug.py --full \
  --output "$HOME/xr-gate-gestures.zip"
```

В релизе также есть `./gesture_debug.sh --full`. Параметры `--hand left|right|both`,
`--prepare 3`, `--hold 4` меняют сценарий и время. Перед записью выключи
`override_controller` или временно передай
`OVERRIDE_CONTROLLER_BLOCK_GESTURES_WHILE_STREAM_PRESENT=0`; иначе новый режим
правильно блокируется существующей настройкой. ZIP содержит `frames.jsonl`,
описание поз и сводку. Для калибровки извлеки из него `frames.jsonl`.

Запусти трекинг с `RUNTIME_APP_TCP=1` (эмуляция для записи может быть выключена).
Из корня исходников во втором терминале:

```bash
python3 runtime_adapters/xr_runtime_adapter/tools/record_emulation_hands.py \
  --calibrate both --output "$HOME/emulation-v3-hands.jsonl"
```

Скрипт предлагает нейтраль, направления **наклоном кисти**, прижатый большой,
раскрытые/согнутые пальцы, trigger, grip, их сочетание с D-pad, A, B, клик панели
и в конце двуручный Menu. Перед следующей позой записывается согнутая нейтраль.
Для записи одной руки можно выбрать `--calibrate right` или `left`.
В JSONL сохраняются все 21 сустава, временные метки, признаки достоверности,
позы кистей/HMD и текущие кнопки/оси. Камеры/видео не записываются.

```bash
bin/runtime_adapters/xr_runtime_adapter/xr_emulation_tool calibrate \
  "$HOME/emulation-v3-hands.jsonl" "$HOME/emulation-v3-calibrated.json" \
  --config runtime_adapters/xr_runtime_adapter/configs/emulation_controller.json

bin/runtime_adapters/xr_runtime_adapter/xr_emulation_tool replay \
  "$HOME/emulation-v3-hands.jsonl" "$HOME/emulation-v3-result.jsonl" \
  --config "$HOME/emulation-v3-calibrated.json"
```

Калибровка сохраняет четыре направления наклона, нейтраль, её разброс и диапазон
сгиба каждого пальца; для каждой
позы нужны минимум 10 достоверных исходных кадров. Наклон только в одной оси
или движение одного большого пальца вместо кисти отклоняются как недостаточные
данные. Инструмент воспроизведения использует тот же C++ код, что живой runtime.
Он выводит кнопки, оси, сгиб и разгибание пальцев в порядке
`index, middle, ring, little`, `thumb_clearance` и `pinch_ratio`.
Существующие выходные файлы не перезаписываются.

Для подписанных поз нейтрали/направлений проверяется достоверность ладони.
Порог отогнутого большого не отбрасывает их из расчёта осей: это независимый
переключатель перемещения, пороги которого можно подобрать отдельно.

Для оценки разгибания учитываются суставы пальца, прежде всего PIP и глубокий
сгиб основания. Загнутый кончик при прямой средней части не должен отпускать
Grip. Если трекер выдаёт согнутый палец вместо разогнутого, восстановить
намерение только по 21 суставу невозможно: такой кадр не превращается в нажатие.
На записи также встречаются позы клика панели с суставами, соответствующими B.
Исправление проверяется воспроизведением записи и регрессионными тестами с
нормализованными координатами; после установки нужен живой тест.
У мизинца DIP не учитывается повторно в угловом признаке: загнутый кончик
уже укорачивает цепочку и не должен дважды препятствовать включению Grip.

Для полной перекалибровки **обеих** рук используй `--full --hand both`.
Полный сценарий включает 66 этапов: обе нейтрали и четыре направления каждой
руки, раскрытые/согнутые пальцы, Trigger и Grip при прямой кисти, наклонах
вперёд/назад и возврате в прямое положение, их комбинацию, отключение осей
большим, A/B, V с двумя положениями большого и двуручный Menu. При
`--prepare 2 --hold 4` запись занимает около семи минут.
Нейтраль выбирай как удобную позу в игре, не подстраиваясь под текущие числа
осей. Для нового профиля будут пересчитаны обе руки; старый JSON удалять не нужно.

### Повторная проверка правого D-pad, Trigger и V

Если левый D-pad уже настроен, используй короткий сценарий:

```bash
python3 runtime_adapters/xr_runtime_adapter/tools/xr_gate_gesture_debug.py \
  --follow-up --prepare 2 --hold 3 \
  --profile "$HOME/emulation-v3.json" --output "$HOME/xr-gate-followup.zip"
```

Замени путь `--profile` на используемый при запуске JSON. Сценарий записывает
нейтраль и четыре направления **только правой руки**, затем Trigger при прямой
кисти и наклонах, V с прижатым/отогнутым большим на обеих руках. Левая рука не
получает меток калибровки осей. В консоли `T` — Trigger, `G` — Grip.
Нейтраль правой выбирай как обычное положение руки в игре; возвращайся именно
в него между направлениями. Меняй наклон кисти, сохраняя положение предплечья.
Для одной руки можно добавить `--hand right` или `--hand left` (для левой —
только диагностика пальцев).

При построении профиля по этой записи обязательно передай **текущий** профиль
через `xr_emulation_tool calibrate ... --config CURRENT.json`: тогда объект
`left` останется прежним. Без `--config` калибровки левой в записи нет и эта
сторона будет выключена. Скрипт ничего не меняет в работающем runtime; V
начинает нажимать кнопку после обновления адаптера.

## Автоматические проверки

```bash
cmake -S runtime_adapters/xr_runtime_adapter -B build/emulation-tests \
  -DCMAKE_BUILD_TYPE=Release -DXR_RUNTIME_ADAPTER_BUILD_TESTS=ON
cmake --build build/emulation-tests --parallel 2
ctest --test-dir build/emulation-tests --output-on-failure
```

Проверяются независимость большого/указательного/мизинца, управление исключительно
наклоном кисти, все новые позы, двуручный Menu, потеря/сброс/замирание источника,
счётчики событий, запись TCP, калибровка и воспроизведение. Совместная работа с
`override_controller`, приоритет физической панели, потеря руки/контроллера и
отпускания проверяются через настоящий TCP-вход адаптера в `hand_plus_controller`
и `controller_buttons_runtime_only`. Старый режим жестов также остаётся под проверкой.
Отдельно проверяются блокировка новых жестов по умолчанию, двуручного Menu,
сохранение физических кнопок и возобновление жестов после защитной задержки.

## Дополнительная калибровка указательного и среднего

Для `button_layout: "middle_grip"` каждая сторона может содержать
`finger_pair_calibration` с `feature: "finger_angles_v1"`. Это необязательная
калибровка только Trigger/Grip; без неё действует прежняя обработка пальцев.
`enabled: false` отключает её отдельно для выбранной руки.

Калибровка содержит четыре массива примеров: `open`, `index`, `middle`, `both`.
Один пример — шесть углов, поделённых на 90 градусов: MCP указательного,
MCP среднего, PIP указательного, PIP среднего, DIP указательного, DIP среднего.
В каждой группе допускается 1–64 примера. `max_distance` (по умолчанию 1)
ограничивает евклидово расстояние до ближайшего примера. Невалидные суставы
и позы за этим пределом отпускают оба канала, включая режим разгибания.
Группы обеих кнопок обеспечивают их одновременную работу; настройка полярности
`trigger_on_curl` / `grip_on_curl` и задержка `button_confirm_ms` сохраняются.
Эта калибровка имеет приоритет над отдельными калибровками Trigger и среднего Grip.

Углы не зависят от масштаба, переноса, жёсткого поворота кисти или зеркального
отражения. Примеры правой руки можно попробовать на левой, однако качество
оптического трекинга и удобные позы каждой руки требуют отдельной проверки.
Настройки большого пальца переносить таким способом нельзя.

Вариант `three_fingers`: движение указательного или среднего отменяет готовность клика.
Перед кликом снова удержи исходную позу: указательный и средний прямые,
безымянный согнут, большой прижат; затем выпрями безымянный.

## Мизинец для клика, отпускание Grip и боковое движение

`thumbstick_click_gesture: "index_middle_little"` заменяет безымянный мизинцем
в отдельном жесте клика. Указательный и средний прямые, безымянный согнут,
большой целиком прижат. Сначала удержи эту позу с согнутым мизинцем в течение
`pose_confirm_ms`, затем выпрями мизинец. Сгибание мизинца отпускает клик.
Старый вариант `three_fingers` сохранён. Оба отдельных жеста требуют
`button_layout: "middle_grip"`; при потере руки и движении указательного или
среднего готовность клика сбрасывается.

`grip_release_threshold` задаёт порог удержания Grip (значение `-1` сохраняет
прежнюю логику). Профиль использует `0.60` вместо общего `curl_off: 0.45`:
при разгибании среднего Grip отпускается на первом новом измерении ниже 0.60.
Порог нажатия и подтверждение нажатия остаются прежними. Это работает как с
`finger_pair_calibration`, так и с обычной калибровкой среднего; настройка
полярности `grip_on_curl` сохраняется. Порог должен быть ниже порога нажатия.

Для D-pad по большому пальцу повышены `thumb_back_on` до `0.98`,
`thumb_back_off` до `0.90`. Дополнительно `thumb_back_side_ratio: 0.80` требует,
чтобы отклонение назад составляло хотя бы 80% бокового отклонения. Проверка
идёт до кругового ограничения осей и после инверсии вперёд/назад. При отказе
обнуляется и аналоговая ось назад, и цифровое направление; намеренные
диагонали с сопоставимыми X/Y сохраняются. Значение ratio `0` сохраняет
прежнюю проверку только абсолютного порога. Режим D-pad по кисти не изменён.

Эмуляция выдаёт X/Y слева и A/B справа, включая касания, изменения кнопок и
счётчики. Кнопки физического контроллера сохраняют свою исходную раскладку.
В SteamVR и Monado общий маппинг сохраняет независимые A/B/X/Y; алиасы для
левой руки по умолчанию отключены.

## Независимый полусогнутый безымянный и записанная поза «назад»

`thumbstick_click_gesture: "ring_finger"` — отдельный канал тачпада для
`button_layout: "middle_grip"`. Используются углы MCP/PIP/DIP безымянного,
а не общий curl, который насыщается уже при согнутой костяшке. Большой,
указательный и средний не входят в распознавание клика. Движение, Trigger,
Grip и клик могут работать вместе. Полные кольца A/B и X/Y остаются отдельными
позами; при удержанном маркере клика сближение большого и указательного их
не вызывает. Неполный щипок в этом режиме не блокирует игровые каналы.

Пороги: `ring_click_mcp_min_degrees`, `ring_click_mcp_max_degrees`,
`ring_click_pip_max_degrees`, `ring_click_dip_max_degrees`; удержание расширяется
на `ring_click_hysteresis_degrees`. Нажатие подтверждается за `button_confirm_ms`,
отпускание — на первом свежем измерении за пределами гистерезиса. После старта,
потери руки или специальной позы сначала покажи отпущенный безымянный.
Старые `layout_default`, `three_fingers`, `index_middle_little` сохранены.

Необязательный блок `left/right.thumb_back_pose` содержит `feature:
"thumb_skeleton_v2"`, `poses` (1–16 векторов по 12 чисел), `max_distance`,
`release_distance`, `ip_max_degrees`, `ip_release_degrees`,
`reference_invert_y`. Близость к записанной позе и изгиб IP позволяют распознать
явный загиб большого, даже если IP оказался внутри старого порога «спрятан».
Эта узкая поза даёт чистое движение назад; `thumb_invert_y` учитывается через
сохранённый `reference_invert_y`. Остальные позы используют прежнюю калибровку.
Блок можно отключить через `enabled: false`.

Дополнительно блок поддерживает `neutral_poses` (до 8 векторов) и
`neutral_distance`: близкое совпадение с записанной нейтралью обнуляет движение.
Это устраняет наблюдавшийся боковой дрейф при клике. Пересекающиеся области
нейтрали и назад отклоняются при загрузке профиля. Для левой руки добавлен только
зеркальный эталон назад; новая нейтраль записывалась и применяется только справа.
Все эти параметры действуют только при D-pad от большого пальца.

В `left/right.ring_click_pose` можно задать `feature: "ring_skeleton_v1"`,
`poses` (1–16 векторов из 9 чисел), `max_distance` и `release_distance`.
Это координаты трёх концов фаланг относительно MCP в осях ладони
(across, normal, forward), нормированные на суммарную длину пальца.
Эталон дополнительно отсекает другую форму пальца при похожих MCP/PIP/DIP.
Большой и формы остальных пальцев в этот эталон не входят. `enabled: false`
отключает только сравнение с эталоном, сохраняя угловой канал клика.


### Отдельный клик раскрытой ладонью

`thumbstick_click_gesture: "open_palm"` выбирает отдельную позу вместо клика
безымянным. Все пять пальцев раскрыты; ладонь направлена к пользователю.
Клик подтверждается за `button_confirm_ms` и удерживается до выхода из позы.
Во время раскрытой позы движение, Trigger и Grip подавлены. Для возврата
игровых каналов нужна отпущенная игровая поза. При старте раскрытую ладонь
можно показать сразу; предварительно сгибать безымянный не требуется.

В этом режиме Menu требует двух раскрытых ладоней от себя в течение
`menu_hold_ms`. Нормаль ладони сравнивается с направлением от центра кисти
к достоверной позиции HMD до дополнительных визуальных yaw-смещений.
Порог входа `palm_facing_on: 0.75`, удержания `palm_facing_off: 0.60` — косинусы.
При повороте ребром обе команды отпускаются. Без достоверного HMD-ориентира
клик и Menu не включаются. Старые режимы и правила Menu в них сохранены.

`left/right.thumb_activity_calibration` — необязательные индивидуальные
эталоны `feature: "thumb_skeleton_v2"`: списки `tucked` и `neutral` (1–16
векторов по 12 чисел), `max_distance: 0.085`, `release_distance: 0.105`.
Близкий эталон прижатого большого выключает D-pad в обоих режимах, включая
эталон назад. Близкая расслабленная нейтраль обнуляет оси, сохраняя touch.
В остальных позах работает прежняя калибровка направлений и её пороги.
`enabled: false` отключает только этот дополнительный блок.


### Выбор исходных grab/pinch-жестов

Эмуляция контроллеров включена по умолчанию. `SIMPLE_GESTURES=1` в окружении
скрипта запуска или `--simple-gestures` у самого `xr_runtime_adapter` выбирает
исходную grab/pinch-схему. Параметр имеет приоритет над `--emulation-controller 1`;
JSON эмуляции в этом режиме не загружается. `--emulation-controller 0` также
сохранён как явное отключение эмуляции. Это не меняет политику блокировки жестов
физическим контроллером и настройки разрешённых сторон.

```bash
SIMPLE_GESTURES=1 ./run_xr_client.sh --config xreal_ultra
```

В Windows Launcher выбери `Gestures (grab / pinch)`. Прежний пункт
`Gestures` называется `Gestures (controller emulation)`; его сохранённое
значение `XR_CONTROLLER_MODE=gestures` и калибровки не меняются.
Вариант `No` отключает обе схемы, сохраняя трекинг головы.
