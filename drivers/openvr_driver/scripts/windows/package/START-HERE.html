SteamVR-драйвер XR Gate в Windows

Русский · English

Это SteamVR-драйвер для Windows x64. Capture и трекинг XR Gate работают в Linux, WSL или Docker, SteamVR и игра — в Windows. Драйвер подключается к серверу xr_gate_app_v1 по TCP 127.0.0.1:45810. Изображение поступает в XREAL через видеоподключение к GPU Windows. Передача USB камер/HID через USB/IP не передаёт DisplayPort-видео.

1. Скачать Windows-пакет

После применения сопровождающего патча и успешного запуска GitHub Actions:

  1. Откройте Actions → XR Gate split build и успешную сборку изменённого commit.
  2. Скачайте artifact xr-gate-steamvr-windows-x64
  3. Распакуйте artifact, затем xr-gate-steamvr-windows-x64-60Hz-direct.zip в постоянную папку, например C:\XR-Gate-SteamVR\60Hz-direct.
  4. Внутри xr_tracking должны находиться driver.vrdrivermanifest, bin\win64\driver_xr_tracking.dll, resources и BAT-файлы.

CI также собирает варианты 90 Hz и extended_sbs. Начните с 60 Hz. Одновременно регистрируйте только один пакет XR Gate. При публикации релиза этим workflow четыре Windows ZIP и файлы SHA-256 также появляются в Release.

2. Установить SteamVR-драйвер

Установите Steam и SteamVR через Steam. Один раз запустите SteamVR, затем закройте его. В распакованной папке xr_tracking дважды щёлкните Install-Driver.bat. Права администратора обычно не требуются. Скрипт ищет SteamVR по зарегистрированному runtime и установке Steam, а если не находит — просит путь к папке SteamVR, например D:\SteamLibrary\steamapps\common\SteamVR.

Скрипт вызывает vrpathreg.exe adddriver и показывает список путей. После регистрации оставьте папку драйвера на месте. Если SteamVR заблокировал add-on, откройте Settings → Startup/Shutdown → Manage Add-ons и включите XR Gate.

Для явного пути в PowerShell:

.\Manage-Driver.ps1 -Action Install -SteamVR 'D:\SteamLibrary\steamapps\common\SteamVR'

Для удаления или смены варианта закройте SteamVR, запустите Uninstall-Driver.bat в старом пакете, затем установите новый. Удаляется только этот зарегистрированный путь драйвера; SteamVR и другие драйверы сохраняются.

3. Подготовить SBS и видеоподключение XREAL

Это разные операции: SBS/3D задаёт стереорежим дисплея очков, а Direct Mode SteamVR передаёт поддерживаемый дисплей под управление композитора.

  1. Подключите очки к USB-C с поддержкой видео либо к подходящему адаптеру DisplayPort/HDMI → USB-C с питанием, подключённому к нужному GPU.
  2. До передачи USB XREAL в WSL включите полный SBS/3D. У XREAL Air 2 Ultra удерживайте Brightness Up (+) примерно 3 секунды до сигнала, как указано в корневом README XR Gate.
  3. В настройках дисплея Windows проверьте стереоразрешение очков, обычно 3840×1080, и выберите 60 Hz для пакета 60 Hz. Эта временная проверка обычного монитора выполняется до захвата дисплея Direct Mode.
  4. Передайте камеры/HID и при необходимости Bluetooth-донгл в WSL, затем запустите XR Gate. Оставьте консоль xr_client открытой. Если WSL предлагает выбор режима, используйте текущий режим дисплея, когда Windows/кнопка очков уже переключили SBS.

После передачи USB в WSL Windows-утилита HID не может управлять тем же устройством. Используйте кнопку очков или Linux-helper; перед Windows-helper остановите XR Gate и верните USB Windows. Переключение режима с переподключением USB может потребовать повторить attach и перезапустить контейнер/runtime.

4. Включить Direct Mode в SteamVR

  1. При работающем XR Gate запустите Test-TCP.bat. Должен появиться xr_gate_app_v1. Успешный TCP ещё не подтверждает качество трекинга: проверьте startup gate и pose_valid.
  2. Запустите SteamVR. Откройте Settings → Developer → Enable Direct Mode, как описано у Valve. В зависимости от версии включите Advanced Settings либо откройте Developer Settings из меню SteamVR, чтобы найти этот пункт.
  3. Если требуется, перезапустите SteamVR. Проверьте изображение VR в очках и реакцию головы/контроллеров, затем запускайте игру.

Direct-Mode-Guide.bat открывает эту инструкцию и запускает SteamVR. Переключатель Direct Mode остаётся ручным шагом: комплект не использует недокументированную GPU-команду и не обещает, что directMode: true принудительно переведёт любой монитор в Direct Mode.

Совместимость конкретного EDID XREAL, GPU и адаптера с Direct Mode нужно проверять на реальном компьютере. Текущий драйвер предоставляет IVRDisplayComponent, но не добавляет новый Windows-драйвер GPU/дисплея. Успешная сборка DLL или TCP-тест не подтверждают возможность захвата этого дисплея Windows в Direct Mode.

Если экран чёрный или Direct Mode недоступен, проверьте видеоподключение к GPU, SBS-разрешение/частоту и логи SteamVR. Экспериментальный запасной вариант: удалить регистрацию direct-пакета и установить соответствующий 60Hz-extended_sbs. Он использует обычный дисплей Windows; координаты его окна может понадобиться изменить в resources/settings/default.vrsettings. Этот путь также требует проверки с оборудованием. Для обычного использования очков остановите SteamVR, используйте Disable Direct Mode, если пункт доступен, верните USB из WSL и переключите очки в 2D аппаратной кнопкой.

TCP-настройки и ежедневный запуск

Windows-пакет задаёт tcp для runtimePoseTransport, runtimeHandTransport и runtimeControllerStateTransport. Настройки в секции xr_tracking файла resources/settings/default.vrsettings меняйте при остановленном SteamVR:

"runtimeTcpHost": "127.0.0.1",
"runtimeTcpPort": 45810,
"runtimeTcpReconnectMs": 500,
"runtimeTcpTimeoutMs": 1000

Host — IPv4-адрес или localhost. Проверки max-age головы/рук/контроллеров сохраняются, обычно 250 мс. Одно фоновое TCP-соединение обслуживает голову и обе руки. При разрыве кеш очищается; переставшие обновляться или повторяемые кадры устаревают. TCP не продлевает ввод старым механизмом controller input hold. В Linux auto остаётся POSIX SHM; в Windows auto выбирает TCP. Явный Windows UDP остаётся доступен, но этот сценарий и WSL-комплект используют TCP.

Ежедневный порядок: SBS/видео → USB в WSL → XR Gate → TCP-тест → SteamVR → игра. Docker публикует 127.0.0.1:45810 Linux-хоста; WSL передаёт localhost в Windows. Не запускайте одновременно прямой WSL-runtime и Docker-runtime на одном порту. Для 90 Hz используйте соответствующий пакет; частоту TCP при необходимости можно повысить до 90 отдельно от физической частоты дисплея очков.

Сборка из исходников и CI

Нужны MSVC x64, CMake/Ninja, Python 3.10+, OpenVR SDK commit 0924064316de3effbcd1acf1e309182a2deb1c05 и nlohmann/json 3.11+ (в CI — 3.11.3). В x64 Developer PowerShell из корня репозитория:

.\drivers\openvr_driver\scripts\windows\build_driver.ps1 `
  -OpenVrSdkRoot C:\src\openvr -NlohmannJsonInclude C:\src\json\single_include `
  -Device xreal_ultra -BuildType Release -DisplayFrequency 60 -DisplayMode direct -BuildTests
ctest --test-dir build\drivers\openvr_driver\windows_Release -C Release --output-on-failure

Результат — build\drivers\openvr_driver\windows_Release\xr_tracking. Отдельный Windows-job выполняет эти тесты и упаковывает варианты 60/90 Hz direct/extended. В hosted CI нет оборудования: загрузку SteamVR, GPU Direct Mode, USB XREAL и Bluetooth необходимо проверять на устройстве.

Источники: Valve: Direct Mode, корневой README XR Gate, Microsoft: сеть WSL.

XR Gate SteamVR driver on Windows

Русская инструкция · English

This package is a Windows x64 SteamVR driver. XR Gate capture/tracking runs in Linux, WSL or a Docker container; SteamVR and the game run in Windows. The driver connects to the runtime's xr_gate_app_v1 TCP server at 127.0.0.1:45810. Display output reaches XREAL through the Windows GPU/video connection. USB/IP for the cameras/HID does not carry DisplayPort video.

1. Download the Windows package

After the accompanying patch has been applied and GitHub Actions has completed:

  1. Open the repository's Actions → XR Gate split build and the successful run for the patched commit.
  2. Download artifact xr-gate-steamvr-windows-x64
  3. Extract the artifact, then extract xr-gate-steamvr-windows-x64-60Hz-direct.zip into a permanent folder, for example C:\XR-Gate-SteamVR\60Hz-direct.
  4. The inner xr_tracking folder must contain driver.vrdrivermanifest, bin\win64\driver_xr_tracking.dll, resources, and the BAT files.

The job also builds 90 Hz and extended_sbs variants. Start with 60 Hz. Register only one XR Gate package at a time. A published release from this workflow also contains the four Windows ZIPs and SHA-256 files.

2. Install the SteamVR driver

Install Steam and SteamVR through Steam. Start SteamVR once, then close it. Inside the extracted xr_tracking folder, double-click Install-Driver.bat. Administrator rights are normally unnecessary. The script locates SteamVR from its registered runtime path or Steam installation; otherwise it asks for the SteamVR folder, for example D:\SteamLibrary\steamapps\common\SteamVR.

It runs vrpathreg.exe adddriver and shows registered paths. Keep the driver folder in place after registration. If SteamVR blocks the add-on, open Settings → Startup/Shutdown → Manage Add-ons and enable XR Gate.

For an explicit path in PowerShell:

.\Manage-Driver.ps1 -Action Install -SteamVR 'D:\SteamLibrary\steamapps\common\SteamVR'

To remove or switch packages: close SteamVR, run Uninstall-Driver.bat in the old package, then install the new package. This removes only that registered driver path, not your SteamVR installation or other drivers.

3. Prepare XREAL SBS and the video connection

These are separate operations: SBS/3D mode changes the glasses' display layout; SteamVR Direct Mode lets the compositor own a supported display.

  1. Connect the glasses to a video-capable USB-C output, or an appropriate powered DisplayPort/HDMI-to-USB-C adapter connected to the intended GPU.
  2. Before forwarding XREAL USB to WSL, enable full SBS/3D. On XREAL Air 2 Ultra, hold Brightness Up (+) for about 3 seconds until the beep, as described in the root XR Gate README.
  3. In Windows Display settings, verify the glasses show the expected stereo resolution, normally 3840×1080, and select 60 Hz for the 60 Hz package. This temporary desktop check happens before Direct Mode takes ownership.
  4. Forward cameras/HID and the optional Bluetooth dongle to WSL, then run XR Gate. Keep its xr_client console open. When offered a display-mode choice in WSL, use the current display mode if Windows/the hardware button already set it.

Once USB is attached to WSL, a Windows HID utility cannot control that same USB device. Use the glasses' hardware button or the Linux-side helper; stop XR Gate and detach USB before using a Windows HID helper. A USB mode switch/reconnect may require attaching USB again and restarting the container/runtime.

4. Enable Direct Mode in SteamVR

  1. With XR Gate running, run Test-TCP.bat. It must report xr_gate_app_v1. Transport success alone does not establish valid tracking: check the startup gate and pose_valid as well.
  2. Start SteamVR. Open Settings → Developer → Enable Direct Mode, following Valve's instructions. Depending on SteamVR version, enable Advanced Settings or open Developer Settings from the SteamVR menu to find this control.
  3. Restart SteamVR if requested. Verify VR content is shown in the glasses and head/controller tracking responds. Start the game only after this check.

Direct-Mode-Guide.bat opens this guide and starts SteamVR. The Direct Mode toggle remains a manual step: this package does not use an undocumented GPU command or claim that changing directMode: true can force any monitor into Direct Mode.

Direct Mode support for the particular XREAL EDID, GPU and adapter must be tested on the real machine. The current driver provides IVRDisplayComponent; it does not add a new Windows GPU/display driver. A successful DLL build or TCP test is not proof that Windows can acquire this display in Direct Mode.

If the display stays black or Direct Mode is unavailable: check the GPU video path, SBS resolution/frequency and SteamVR logs. As an experimental alternative, unregister the direct package and install the matching 60Hz-extended_sbs package. It uses an ordinary desktop display; its window coordinates may need adjustment in resources/settings/default.vrsettings. This fallback also needs hardware testing. To return the display to normal use, stop SteamVR, use its Disable Direct Mode control if available, detach USB from WSL, and switch the glasses back to 2D with their hardware control.

TCP settings and daily startup

The Windows package sets runtimePoseTransport, runtimeHandTransport, and runtimeControllerStateTransport to tcp. Edit the xr_tracking section of resources/settings/default.vrsettings while SteamVR is stopped:

"runtimeTcpHost": "127.0.0.1",
"runtimeTcpPort": 45810,
"runtimeTcpReconnectMs": 500,
"runtimeTcpTimeoutMs": 1000

Host accepts an IPv4 literal or localhost. Pose/hand/controller max-age settings remain available (normally 250 ms). One background TCP connection serves the head and both hands. On disconnect the cached streams are cleared; quiet or replayed frames expire. TCP does not use the historical controller input hold. Linux auto remains POSIX SHM; Windows auto selects TCP. Explicit Windows UDP is still selectable, but this guide and the WSL bundle use TCP.

Daily order: SBS/video → USB into WSL → XR Gate → TCP test → SteamVR → game. Docker publishes 127.0.0.1:45810 on its Linux host; WSL's localhost forwarding then exposes it to Windows. Do not start the direct WSL runtime and Docker runtime on the same port simultaneously. For a 90 Hz setup, choose the matching package and optionally set the runtime TCP output rate to 90; this is separate from the glasses' display refresh rate.

Build from source / CI

Use MSVC x64, CMake/Ninja, Python 3.10+, OpenVR SDK commit 0924064316de3effbcd1acf1e309182a2deb1c05, and nlohmann/json 3.11+ (CI pins 3.11.3). From an x64 Developer PowerShell in the repository root:

.\drivers\openvr_driver\scripts\windows\build_driver.ps1 `
  -OpenVrSdkRoot C:\src\openvr -NlohmannJsonInclude C:\src\json\single_include `
  -Device xreal_ultra -BuildType Release -DisplayFrequency 60 -DisplayMode direct -BuildTests
ctest --test-dir build\drivers\openvr_driver\windows_Release -C Release --output-on-failure

Output: build\drivers\openvr_driver\windows_Release\xr_tracking. The separate Windows CI job runs the same tests and packages 60/90 Hz direct/extended variants. No hardware is available on hosted CI: actual SteamVR loading, GPU Direct Mode, XREAL USB and Bluetooth need on-device validation.

Sources: Valve Direct Mode help, XR Gate root README, Microsoft WSL networking.
