XR Gate on Windows

Desktop launcher

The app header links to the project and displays the name from XR_DEVICE_NAME (Device: XREAL ULTRA in the XREAL preset). USB states are CONNECTED (available to Windows), SHARED (attached to WSL) and NOT CONNECTED (not found).

Attach USB devices supports Cancel USB operation; closing the window also cancels it. Each usbipd command stops after 30 seconds (XR_USB_COMMAND_TIMEOUT in .env, 5–120 seconds); the desktop USB action stops after three minutes. Some selected devices may already be attached after cancellation: check List USB devices, reconnect the selected adapter if necessary, and retry. Leave Bluetooth BUSID empty for automatic VID:PID selection after a reboot or port change.

Extract the complete Windows ZIP and open XR-Gate.exe. .NET 10 is included; no separate .NET installation is needed. Keep the supplied scripts and subfolders next to the executable.

  1. In Settings, select the hardware preset and dedicated Bluetooth dongle if needed. Hardware identifiers, modules, paths, geometry and controller profiles stay in hardware/*.env and .env.
  2. Click Install / continue. Follow the displayed Windows restart, first Ubuntu login or Ubuntu restart instructions, then continue installation.
  3. Enable SBS and Extend these displays in Windows. Close SteamVR and use Select glasses display if automatic identification is unavailable.
  4. Click Start VR. Complete calibration in the tracking console. SteamVR starts after fresh valid head poses arrive; WSL stays active while the launcher is open.
  5. Use Stop tracking & return USB to stop the managed session. Closing the launcher also requests a clean stop.

The driver follows the current glasses refresh rate. An unsupported or unknown frequency selects 60 Hz with a warning. For an unambiguously identified output, XR Gate tests and applies 60 Hz without changing resolution; otherwise it asks for display selection. The main monitor is not guessed. Disable XR_AUTO_DRIVER_FREQUENCY for manual selection. Display matching uses saved selection, XR_DISPLAY_NAME, a unique XR_DISPLAY_MATCH from the hardware preset. Resolution alone does not identify the glasses.

Diagnostics and Refresh status can be cancelled and stop after 60 seconds. Linux diagnostic commands stop after 10 seconds. Status separates the configured driver frequency from the current glasses display mode; an unidentified display has an unknown refresh rate.

Diagnostics and Save log collect troubleshooting output. Run provides USB attachment and Bluetooth controller selection; tools provides Diagnostics, registration and tracking checks. The Launcher configuration tests workflow publishes a portable xr-gate-windows-wsl-usbip-launcher artifact; the full Windows build includes the launcher and driver variants in xr-gate-windows-wsl-usbip.zip, with a 60 Hz fallback always included.

The command-line instructions below remain available.

1. Download and prepare

  1. Use Windows 11 x64 and an AVX2-capable CPU.
  2. Install Steam and SteamVR. Open SteamVR once, then close it.
  3. Download xr-gate-windows-wsl-usbip.zip from Releases, or the xr-gate-windows-wsl-usbip artifact from your CI run.
  4. Extract the ZIP to a permanent folder. Open its xr-gate-windows-wsl-usbip folder. Keep the drivers, hardware, linux and windows subfolders together.
  5. Open a regular Windows PowerShell in this folder. Run all commands below there.

Bluetooth adapter for WSL2

Tested adapter: ASUS USB-BT500 (0b05:190e), with Ubuntu 24.04 in WSL2 and kernel 6.18.54.1-microsoft-standard-WSL2.

Use a dedicated USB Bluetooth adapter for XR Gate and leave the system adapter with Windows. USB forwarding transfers the whole adapter to WSL; while attached, Windows cannot use it for Bluetooth keyboards, mice, headphones or other devices. Returning the adapter to Windows makes it available there again. See the usbipd WSL documentation.

In the desktop launcher, enable Enable Bluetooth. For ASUS USB-BT500, clear Bluetooth USB BUSID and keep Bluetooth VID:PID at 0b05:190e, as supplied by the XREAL preset. Save settings, then use Attach USB devices. The adapter's current BUSID is resolved automatically, including after changing USB ports.

For the scripts, set XR_BLUETOOTH=1 and XR_BLUETOOTH_USB_ID=0b05:190e in .env, with XR_BLUETOOTH_BUS_ID empty. You can also pass -BluetoothUsbId 0b05:190e explicitly. The generic hardware template leaves VID:PID empty so another adapter can be configured.

Selection priority: explicit BUSID, explicit XR_BLUETOOTH_INSTANCE_ID, configured VID:PID, then the saved adapter when both selectors are empty. An explicit BUSID must exist; it never silently falls back to VID:PID. A configured VID:PID never falls back to an unrelated system adapter. If several devices match, the saved matching instance is used; otherwise select one by BUSID. Bluetooth must be enabled; setting a default VID:PID alone does not attach a device.

MediaTek limitation in the tested kernel: the built-in MT7922 (0489:e0e2) did not initialize because the stock WSL 6.18.54.1 configuration has CONFIG_BT_HCIBTUSB_MTK disabled. Installing firmware or seeing the adapter in lsusb does not add the missing kernel driver support. Switching the Ubuntu distribution to 26.04 inside WSL does not enable it either. See the configuration for that kernel version. Other adapters may work if their driver and firmware are supported by the running WSL kernel; ASUS USB-BT500 is the verified option for this setup.

2. Configure your hardware (skip for XREAL Ultra)

For XREAL Air 2 Ultra, the supplied preset is ready to use. Create your settings file once:

if (!(Test-Path .env)) { Copy-Item .env.example .env }

For another device, copy the generic template:

Copy-Item hardware\generic.env.example hardware\my-device.env

Edit hardware/my-device.env, then set XR_HARDWARE_ENV=hardware/my-device.env in .env.

  1. Set XR_PROFILE to the runtime profile and XR_TARGET_DEVICE to its device name.
  2. Set XR_USB_IDS to the camera/IMU VID:PID pairs. For a manual selection, run usbipd list and set XR_USB_BUS_IDS in .env. For multiple devices, separate the IDs with commas. XR_USB_INSTANCE_IDS accepts stable Windows USB instance paths instead.
  3. Set Linux camera, HID, serial and input paths when needed: XR_CAMERA_DEVICE, XR_HIDRAW_DEVICES, XR_SERIAL_DEVICES, XR_INPUT_DEVICES. Enable XR_REQUIRE_CAMERA=1 if the profile uses a camera.
  4. Set XR_DEVICE_ACCESS_SCRIPT to the matching setup script inside the release, or leave it empty. List the required Linux modules in XR_KERNEL_MODULES.
  5. Set XR_WINDOW_WIDTH, XR_WINDOW_HEIGHT, XR_RENDER_WIDTH, XR_RENDER_HEIGHT, XR_DISPLAY_FREQUENCY_HZ and the optical settings for your display.

To override saved choices, put the setting directly in .env. Select a frequency and XR_DISPLAY_MODE (direct or extended_sbs) included in the archive. For a dedicated Bluetooth adapter, set XR_BLUETOOTH_USB_ID to its VID:PID for automatic selection, or XR_BLUETOOTH_BUS_ID for an explicit port selection. Set XR_BLUETOOTH=0 to disable a saved dongle, or XR_GEARVR=0 to disable Gear VR. Set XR_STEAMVR_PATH if SteamVR is not found automatically.

3. Install

  1. Double-click INSTALL.cmd, or run:
.\INSTALL.cmd

For Gear VR controllers, use:

.\INSTALL.cmd -GearVR
  1. Approve the administrator prompt. Restart Windows and run the same command again.
  2. If Ubuntu opens for the first time, create a Linux username and password, enter exit, then run the installation command again.
  3. If asked to restart Ubuntu, save your work in it and run:
wsl --terminate Ubuntu-24.04
.\INSTALL.cmd

Use the distribution name from XR_DISTRIBUTION if you changed it. Repeat -GearVR if used.

  1. If driver registration was deferred, close SteamVR and run:
.\DRIVER.cmd

4. Select the display

For extended_sbs:

  1. Connect the glasses' video input to the Windows GPU and enable SBS on the glasses.
  2. In Windows display settings, choose Extend these displays. Set the glasses' resolution and frequency to the values in your hardware env.
  3. Disable SteamVR Direct Mode, then close SteamVR.
  4. Run:
.\DISPLAY.cmd
  1. Select the glasses' row using Windows Identify. To save a fixed output name instead, set XR_DISPLAY_NAME in .env and run the command again.

For direct, use Direct-Mode-Guide.bat in the selected drivers/<frequency>Hz-direct/xr_tracking folder.

5. Start

  1. Connect the devices. Place IMU controllers on a flat surface and keep them still.
  2. Run:
.\RUN.cmd
  1. Complete the startup prompts and calibration in the opened console. Keep it open and wait for SteamVR.
  2. Enable the XR Gate add-on in SteamVR if prompted. Check the headset, then start your game.

For the next session, connect the devices and run RUN.cmd again. After changing display ports, close SteamVR and repeat DISPLAY.cmd.

To start the runtime without opening SteamVR:

.\CONSOLE.cmd

6. Pair Gear VR controllers

  1. Enable Enable Bluetooth in Settings and choose its USB adapter.
  2. Stop tracking and put controllers into pairing mode.
  3. Click Run → Pair Bluetooth controllers and choose left/right devices by name. MAC addresses distinguish identical names. Either side can remain Not selected to disable it in the saved config.
  4. Click Connect & save. Pairing, trust and connect run automatically and MAC addresses are saved to ~/xr-gate-wsl/config/override_controller.json. The previous config is backed up; connection failure leaves it unchanged.
  5. Click Start VR. The supplied GearVR profile needs no separate registration afterward. Use Register / train controllers to change button mappings or configure other profiles.

The PowerShell operation also provides interactive name selection:

powershell -NoProfile -ExecutionPolicy Bypass -File .\XrGate-Wsl.ps1 -Action Pair

The Ubuntu package includes bin/scripts/override_controller/bluetooth_controllers.py beside start_override_controller.sh. Automatic identity assignment supports the gearvr_ble backend selected in the controller configuration.

7. Stop or change settings

Stop tracking & return USB and window closing wait for every owned runtime service before verifying USB detach, including an Attach-only session. A failure on one device does not skip the other selected devices. Incomplete cleanup keeps the window open for log inspection and another Stop attempt.

  1. Close SteamVR.
  2. Press Ctrl+C in the runtime console and wait for it to stop.
  3. To return USB devices to Windows, run:
.\DETACH.cmd

After changing hardware settings, attach the devices and start again. After changing the release, driver frequency or display mode in .env, repeat INSTALL.cmd and the display setup.

8. If startup fails

Run:

.\DOCTOR.cmd

With the runtime console still open, test tracking:

powershell -NoProfile -ExecutionPolicy Bypass -File .\XrGate-Wsl.ps1 -Action Test

If SteamVR reports an invalid desktop display, close SteamVR, check Extend, the resolution and frequency in Windows, then repeat DISPLAY.cmd and RUN.cmd.

CI platform selection

XR Gate split build → Run workflow offers independent Build ubuntu release and Build windows release (includes SteamVR driver) switches. Build either or both. xr-gate-windows-wsl-usbip.zip includes the self-contained WPF app and SteamVR drivers.

A Windows-only installer pins an existing Ubuntu runtime/models release. It needs no Linux rebuild. If no usable runtime release is found or GitHub lookup is unavailable, Windows still builds with XR_RELEASE_TAG=latest and a warning. Before installing, publish an Ubuntu runtime/models release or select an available runtime tag in launcher Settings. Publishing uploads only selected platforms.
