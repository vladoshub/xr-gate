# XR Gate в Windows (установка через WSL2)

[English](README.md) · [Русский](README.ru.md)

## Запуск через приложение

**Attach USB devices** можно прервать кнопкой **Cancel USB operation** или закрытием окна. Каждая команда `usbipd` ограничена 30 секундами (`XR_USB_COMMAND_TIMEOUT` в `.env`, диапазон 5–120); вся USB-операция в приложении — тремя минутами. При отмене завершаются временные дочерние процессы. При отмене кнопкой часть USB-устройств может остаться подключённой; **Stop tracking & return USB** освобождает выбранные устройства. Закрытие окна также выполняет остановку и USB-detach, даже если нажимали только Attach. Перед пробросом BUSID заново определяется по выбранному Windows instance. Для автоматического выбора Bluetooth по VID:PID оставьте его BUSID пустым.

Распакуйте весь **xr-gate-windows-wsl-usbip.zip** и откройте **XR-Gate.exe**. Это WPF-приложение для Windows x64 со встроенным .NET 10: отдельно устанавливать .NET или SDK пользователю не нужно. Сохраните скрипты и подпапки рядом с `.exe`.

1. В **Settings** выберите аппаратный профиль и включите Bluetooth, если используете BLE-контроллеры. Готовый профиль выбирает ASUS USB-BT500 по VID:PID при пустом Bluetooth BUSID; для ручного выбора или другого адаптера используйте **List USB devices**. Список появится прямо под кнопкой в Settings. Если usbipd не найден, сначала выполните **Install / continue**. USB-идентификаторы, модули Linux, геометрия, оптика, шаблоны контроллеров и правила поиска дисплея задаются в `hardware/*.env`; переопределения сохраняются в `.env`.
2. Нажмите **Install / continue**. Программа объяснит, когда нужна перезагрузка Windows, первый вход в Ubuntu или её перезапуск. После этого продолжите установку. Права администратора запрашиваются для установки зависимостей и первоначального разрешения передачи USB.
3. Для SBS включите SBS на очках и «Расширить эти экраны» в Windows. Закройте SteamVR и нажмите **Select glasses display**, если дисплей не определился автоматически.
4. Нажмите **Start VR**, пройдите стартовые подсказки и калибровку в консоли трекинга. SteamVR откроется после появления актуальной валидной позы головы. Лаунчер удерживает выбранную Ubuntu работающей. Вверху окна показаны ссылка на проект, читаемое имя из `XR_DEVICE_NAME` и состояние USB-устройства: **CONNECTED** — доступно Windows; **SHARED** — передано в WSL; **NOT CONNECTED** — не найдено по выбранному аппаратному профилю. Статус обновляется без переподключения USB.
5. **Stop tracking & return USB** корректно останавливает управляемый XR Gate и возвращает его устройства Windows. Закрытие лаунчера дожидается остановки всех процессов управляемой сессии и проверяет USB-detach. Если очистка не завершилась, окно остаётся открытым с ошибкой и возможностью повторить Stop. При сбое одного USB-detach проверяются и остальные выбранные устройства.

По умолчанию включён автоматический подбор драйвера (`XR_AUTO_DRIVER_FREQUENCY=1`): при установке и запуске VR выбирается и регистрируется вариант под текущую частоту очков в Windows. Если совпадения нет, выбирается **60 Гц** и выводится предупреждение. Если выход очков однозначно определён, программа также проверяет и устанавливает ему 60 Гц, сохраняя разрешение. Если Windows не принимает режим, запуск останавливается с объяснением. При неизвестном или неоднозначном дисплее выбирается драйвер 60 Гц с предупреждением, а перед запуском desktop VR нужно явно выбрать очки; частота основного монитора не используется наугад. Идентификация использует явно заданное имя выхода из `.env`, сохранённый идентификатор дисплея или однозначное совпадение по `XR_DISPLAY_MATCH` из аппаратного профиля. Одно лишь разрешение не считается идентификатором очков. В Direct Mode выход может быть скрыт — тогда используется запасной вариант 60 Гц. Для принудительной ручной частоты отключите автоматический подбор.

**Diagnostics** и **Refresh status** можно отменить; время выполнения ограничено 60 секундами. Для отдельных диагностических команд Linux действует лимит 10 секунд: зависшая проверка отмечается предупреждением, остальные продолжаются. Статус отдельно показывает настроенную частоту драйвера и текущий режим найденного дисплея очков в Windows. Если дисплей не определён, его текущая частота остаётся неизвестной.

В **Controllers & tools** доступны передача USB, сопряжение Bluetooth, регистрация контроллеров, регистрация драйвера и проверка трекинга. Сопряжение, выбор дисплея и регистрация открывают интерактивные консоли. **Diagnostics** и **Save log** помогают собрать диагностику. Сохранение настроек в GUI сохраняет дополнительные параметры и комментарии `.env`; после внешнего редактирования файла заново откройте лаунчер.

Для смены аппаратного профиля используйте **Browse…**. Наследуемые поля и подпись контроллеров обновятся сразу; явные переопределения сохранятся. В `.env` записываются изменённые поля, чтобы случайно не закреплять все старые значения профиля. **List USB devices** доступна и во время трекинга. У проверки трекинга и списка USB есть отмена; незаконченные TCP-сообщения не продлевают общий тайм-аут.

Если настройки не читаются, открывается **режим восстановления** с путём к проблемному файлу. Можно открыть файл, исправить и перечитать его либо нажать **Back up & reset this file** для `.env` или кэша состояния. Исходный файл сохраняется под уникальным именем. Аппаратные профили исправляются или выбираются заново. Восстановление не останавливает уже работающий runtime и не возвращает USB: перед повторной установкой после сброса состояния остановите его консоль через Ctrl+C.

При включённом Bluetooth подготовка ожидает настоящий HCI-контроллер. `XR_BLUETOOTH_READY_TIMEOUT` задаёт ожидание готовности (1–120 секунд), `XR_CONTROLLER_INITIAL_SCAN_MS` — начальное сканирование контроллеров (1–600000 мс). Значения переопределяются в аппаратном env или `.env`.

При обновлении закройте приложение и замените **весь архив**, включая скрипты и `windows/DeadlineLineReader.cs`. Свой `.env` сохраните. При смене релиза или варианта драйвера выполните Install / continue. Изменения лаунчера — в [CHANGELOG.md](CHANGELOG.md).

Если при поиске SteamVR упоминается отсутствующий диск, проверьте **Settings > SteamVR folder** (`XR_STEAMVR_PATH`). Очистите поле для автоматического поиска либо укажите папку установленного SteamVR. Устаревшие пути OpenVR и библиотек Steam на отсутствующие диски пропускаются. Установка Linux может завершиться с предупреждением об отложенной регистрации; после исправления пути нажмите **Controllers & tools > Register SteamVR driver**.

### Сборка силами CI

- **Launcher configuration tests** выполняет C#-проверки, проверяет вызов Windows PowerShell, собирает самостоятельный `.exe` и запускает настоящее окно WPF в тестовом режиме. Artifact **xr-gate-windows-wsl-usbip-launcher** содержит `.exe` и скрипты; установка скачает драйверы и runtime из выбранного релиза. Этот workflow можно запустить вручную без полной Linux-сборки.
- **XR Gate split build** с галочкой **Build windows release (includes SteamVR driver)** кладёт `.exe` в общий **xr-gate-windows-wsl-usbip.zip** вместе с выбранными Windows-драйверами. Вариант 60 Гц включается всегда, даже если запрошена только другая частота.
- Для локальной сборки установите .NET 10 SDK в Windows и выполните из репозитория `powershell -NoProfile -ExecutionPolicy Bypass -File win/launcher/build.ps1`. Результат: `out/windows-launcher/XR-Gate.exe`.

Ниже остаётся инструкция для запуска командами.

## 1. Скачайте и подготовьте

1. Нужны Windows 11 x64 и процессор с поддержкой AVX2.
2. Установите Steam и SteamVR. Один раз откройте SteamVR, затем закройте его.
3. Скачайте **xr-gate-windows-wsl-usbip.zip** из [Releases](https://github.com/vladoshub/xr-gate/releases) или artifact **xr-gate-windows-wsl-usbip** из своего запуска CI.
4. Распакуйте ZIP в постоянную папку. Откройте вложенную папку `xr-gate-windows-wsl-usbip`. Сохраните подпапки `drivers`, `hardware`, `linux` и `windows` вместе.
5. Откройте в этой папке обычный Windows PowerShell. Все команды ниже выполняйте в нём.

### Bluetooth-адаптер для WSL2

**Проверенный адаптер: ASUS USB-BT500** (`0b05:190e`), Ubuntu 24.04 в WSL2, ядро `6.18.54.1-microsoft-standard-WSL2`.

**Рекомендуется использовать для XR Gate отдельный USB Bluetooth-адаптер, а системный оставить Windows.** Проброс USB передаёт адаптер целиком в WSL; пока он подключён туда, Windows не может использовать его для Bluetooth-клавиатуры, мыши, наушников и других устройств. После возврата адаптера Windows снова получает к нему доступ. См. [документацию usbipd для WSL](https://github.com/dorssel/usbipd-win/wiki/WSL-support).

В лаунчере включите **Enable Bluetooth**. Для ASUS USB-BT500 очистите **Bluetooth USB BUSID** и оставьте в **Bluetooth VID:PID** значение `0b05:190e` из готового профиля XREAL. Сохраните настройки и нажмите **Attach USB devices**. Текущий BUSID адаптера определится автоматически, в том числе после смены USB-порта.

Для запуска скриптами укажите `XR_BLUETOOTH=1` и `XR_BLUETOOTH_USB_ID=0b05:190e` в `.env`, оставив `XR_BLUETOOTH_BUS_ID` пустым. Также можно явно передать `-BluetoothUsbId 0b05:190e`. В универсальном аппаратном шаблоне VID:PID оставлен пустым для настройки другого адаптера.

**Приоритет выбора:** явный BUSID, явный `XR_BLUETOOTH_INSTANCE_ID`, настроенный VID:PID, затем сохранённый адаптер при пустых селекторах. Указанный BUSID должен существовать: незаметной подмены на выбор по VID:PID нет. Настроенный VID:PID не заменяется посторонним системным адаптером. При нескольких совпадениях используется сохранённый экземпляр с тем же VID:PID; если его нет, выберите один по BUSID. Bluetooth должен быть включён: само значение VID:PID по умолчанию не запускает проброс устройства.

**Ограничение MediaTek в проверенном ядре:** встроенный MT7922 (`0489:e0e2`) не инициализируется, поскольку в штатной конфигурации WSL `6.18.54.1` отключён `CONFIG_BT_HCIBTUSB_MTK`. Установка прошивок или наличие адаптера в `lsusb` не добавляет недостающую поддержку драйвера в ядре. Переход на дистрибутив Ubuntu 26.04 внутри WSL также её не включает. См. [конфигурацию этой версии ядра](https://github.com/microsoft/WSL2-Linux-Kernel/blob/linux-msft-wsl-6.18.54.1/arch/x86/configs/config-wsl). Другие адаптеры могут работать при поддержке их драйвера и прошивок текущим ядром WSL; для этой конфигурации проверен ASUS USB-BT500.

## 2. Настройте оборудование (пропустите для XREAL ULTRA)

Для XREAL Air 2 Ultra готовый профиль уже настроен. Один раз создайте файл своих настроек:

~~~powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
~~~

Для другого устройства скопируйте универсальный шаблон:

~~~powershell
Copy-Item hardware\generic.env.example hardware\my-device.env
~~~

Отредактируйте `hardware/my-device.env`, затем укажите `XR_HARDWARE_ENV=hardware/my-device.env` в `.env`.

1. Укажите профиль запуска в `XR_PROFILE` и имя устройства в `XR_TARGET_DEVICE`.
2. Укажите VID:PID камер и IMU в `XR_USB_IDS`. Для ручного выбора выполните `usbipd list` и задайте `XR_USB_BUS_IDS` в `.env`. Для нескольких устройств разделите BUSID запятыми. Вместо них можно задать постоянные пути Windows USB instance в `XR_USB_INSTANCE_IDS`.
3. При необходимости задайте Linux-пути камеры, HID, serial и устройств ввода: `XR_CAMERA_DEVICE`, `XR_HIDRAW_DEVICES`, `XR_SERIAL_DEVICES`, `XR_INPUT_DEVICES`. Если профиль использует камеру, включите `XR_REQUIRE_CAMERA=1`.
4. Укажите подходящий скрипт настройки из релиза в `XR_DEVICE_ACCESS_SCRIPT` или оставьте поле пустым. Перечислите нужные модули Linux в `XR_KERNEL_MODULES`.
5. Задайте `XR_WINDOW_WIDTH`, `XR_WINDOW_HEIGHT`, `XR_RENDER_WIDTH`, `XR_RENDER_HEIGHT`, `XR_DISPLAY_FREQUENCY_HZ` и оптические параметры своего дисплея.

Чтобы переопределить сохранённый выбор, укажите настройку прямо в `.env`. Выбирайте частоту и `XR_DISPLAY_MODE` (`direct` или `extended_sbs`), которые есть в архиве. Для отдельного Bluetooth-адаптера укажите его VID:PID в `XR_BLUETOOTH_USB_ID` для автоматического выбора либо BUSID в `XR_BLUETOOTH_BUS_ID` для явного выбора порта. Для отключения сохранённого донгла укажите `XR_BLUETOOTH=0`; для отключения Gear VR — `XR_GEARVR=0`. Если SteamVR не найден автоматически, задайте `XR_STEAMVR_PATH`.

## 3. Установите

1. Дважды щёлкните **INSTALL.cmd** или выполните:

~~~powershell
.\INSTALL.cmd
~~~

Для контроллеров Gear VR используйте:

~~~powershell
.\INSTALL.cmd -GearVR
~~~

2. Подтвердите запрос прав администратора. Перезапустите Windows и повторите ту же команду.
3. Если Ubuntu открылась впервые, создайте имя Linux-пользователя и пароль, введите `exit` и повторите команду установки.
4. Если запрошен перезапуск Ubuntu, сохраните в ней работу и выполните:

~~~powershell
wsl --terminate Ubuntu-24.04
.\INSTALL.cmd
~~~

Если меняли `XR_DISTRIBUTION`, используйте указанное там имя дистрибутива. Повторите `-GearVR`, если использовали его.

5. Если регистрация драйвера отложена, закройте SteamVR и выполните:

~~~powershell
.\DRIVER.cmd
~~~

## 4. Выберите дисплей

Для **extended_sbs**:

1. Подключите видеовход очков к видеокарте Windows и включите SBS на очках.
2. В настройках дисплея Windows выберите **Расширить эти экраны**. Установите для очков разрешение и частоту из аппаратного env.
3. Отключите прямой режим SteamVR и закройте SteamVR.
4. Выполните:

~~~powershell
.\DISPLAY.cmd
~~~

5. Выберите строку очков по кнопке **Определить** в Windows. Чтобы закрепить имя выхода, укажите `XR_DISPLAY_NAME` в `.env` и повторите команду.

Для **direct** используйте `Direct-Mode-Guide.bat` в выбранной папке `drivers/<частота>Hz-direct/xr_tracking`.

## 5. Запустите

Необязательная настройка `XR_HMD_MAX_AGE_MS` в `.env` задаёт максимальный
возраст исходной позы HMD (по умолчанию 250 мс). Значение `500` позволяет
проверить временный обход потери позы при задержках временных меток в WSL;
оно не уменьшает задержку сенсоров и увеличивает время обнаружения их остановки.

1. Подключите устройства. Положите IMU-контроллеры на ровную поверхность и не двигайте их.
2. Выполните:

~~~powershell
.\RUN.cmd
~~~

3. Пройдите стартовые подсказки и калибровку в открывшейся консоли. Оставьте её открытой и дождитесь SteamVR.
4. При запросе включите дополнение XR Gate в SteamVR. Проверьте гарнитуру и запустите игру.

Для следующего сеанса подключите устройства и снова запустите **RUN.cmd**. После смены порта дисплея закройте SteamVR и повторите **DISPLAY.cmd**.

Для запуска трекинга без открытия SteamVR:

~~~powershell
.\CONSOLE.cmd
~~~

## 6. Подключите контроллеры Gear VR

При включённом Bluetooth **Install / continue** устанавливает пакеты прошивок Ubuntu и настраивает их доступность ядру WSL после перезапуска. **Attach USB devices** также проверяет и восстанавливает эту настройку, поэтому её можно применить к существующей установке. Если уже подключённый выбранный донгл не инициализировался, переподключается только он. Камера и другие USB-устройства остаются подключёнными.

Драйвер `btusb` берётся из ядра WSL; установщик добавляет прошивки и исправляет доступ к ним из пространства монтирования ядра. Для этого используется служба `xr-gate-wsl-firmware.service`, которая запускается перед Bluetooth. Она не зависит от расположения папки Windows с лаунчером. Это относится и к ситуации, когда файл есть в `/lib/firmware`, но ядро пишет `Direct firmware load ... failed with error -2`.

Параметры можно переопределить в `.env` или аппаратном профиле:

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `XR_WSL_FIRMWARE` | `1` | Автоматически восстанавливать доступ к прошивкам; `0` отключает службу при следующем Attach/Install |
| `XR_BLUETOOTH_FIRMWARE_PACKAGES` | `linux-firmware,zstd` | Пакеты Ubuntu, которые нужно установить |
| `XR_WSL_FIRMWARE_SOURCE` | `/lib/firmware` | Каталог прошивок в Ubuntu |
| `XR_WSL_FIRMWARE_PATH` | `/mnt/wsl/xr-gate-firmware` | Общий с ядром каталог, отдельная подпапка `/mnt/wsl` |
| `XR_WSL_FIRMWARE_FILES` | пусто | Необязательные относительные имена файлов через запятую; при пустом значении используются запросы Bluetooth из журнала ядра |

Прошивки `.zst`, `.xz` и `.gz` при необходимости распаковываются рядом с исходными файлами для совместимости с ядром WSL. Загрузка выполняется через пакеты Ubuntu. Проверяется HCI именно выбранного USB-донгла, даже если в WSL подключено несколько Bluetooth-адаптеров.

1. Включите Bluetooth через `XR_BLUETOOTH=1` в `.env`. Для ASUS USB-BT500 оставьте `XR_BLUETOOTH_BUS_ID` пустым и используйте `XR_BLUETOOTH_USB_ID=0b05:190e` либо укажите явный BUSID для другого выбора. Затем подключите устройства:

~~~powershell
.\USB.cmd
~~~

2. Остановите трекинг, включите режим сопряжения на контроллерах и нажмите **Pair Bluetooth controllers** в приложении.
3. Выберите **Left controller** и **Right controller** по имени. MAC показан рядом с именем, чтобы различать одинаковые устройства. **Not selected** отключает соответствующую сторону в конфиге; выбрать хотя бы одну сторону обязательно. Одно устройство нельзя назначить обеим рукам.
4. Нажмите **Connect & save**. Программа выполнит pairing, trust и connect, сохранит MAC и идентификаторы устройств в `~/xr-gate-wsl/config/override_controller.json` и включит их запуск. Существующие назначения кнопок и настройки сохраняются для выбранных сторон. Перед заменой конфигурации создаётся резервная копия. Если подключение не удалось, исходный конфиг остаётся без изменений.
5. Запустите **Start VR**. Для штатного GearVR-профиля отдельная регистрация после этого не нужна. **Register / train controllers** остаётся для изменения назначений кнопок и других профилей.

Из PowerShell та же операция доступна с интерактивным выбором имён:

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\XrGate-Wsl.ps1 -Action Pair
~~~

Linux-скрипт включён в Ubuntu-релиз рядом со `start_override_controller.sh`. Пример самостоятельного запуска из корня распакованного Linux-пакета:

~~~bash
python3 bin/scripts/override_controller/bluetooth_controllers.py \
  --config "$HOME/.config/xr_tracking/override_controller/default.json" \
  --template bin/override_controller/configs/empty_gearvr.json
~~~

Автоматическая запись идентификаторов реализована для backend `gearvr_ble`, который берётся из выбранного конфига. Для остальных backend используйте регистрацию/обучение. Кнопки, оптика и USB VID:PID не зашиты в программу.

## 7. Остановите или измените настройки

1. Закройте SteamVR.
2. Нажмите **Ctrl+C** в консоли трекинга и дождитесь остановки.
3. Для возврата USB-устройств Windows выполните:

~~~powershell
.\DETACH.cmd
~~~

После изменения аппаратных настроек подключите устройства и запустите снова. После смены релиза, частоты драйвера или режима дисплея в `.env` повторите **INSTALL.cmd** и настройку дисплея.

## 8. Если не запускается

Выполните:

~~~powershell
.\DOCTOR.cmd
~~~

Не закрывая консоль трекинга, проверьте его:

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\XrGate-Wsl.ps1 -Action Test
~~~

Если SteamVR сообщает о неверном дисплее рабочего стола, закройте SteamVR, проверьте расширение экранов, разрешение и частоту в Windows, затем повторите **DISPLAY.cmd** и **RUN.cmd**.

## Выбор сборки в CI

В **XR Gate split build → Run workflow** переключатели независимы:

- **Build ubuntu release** — сборка Ubuntu 24.04/26.04, Linux-компонентов, моделей Mercury и unpack helper.
- **Build windows release (includes SteamVR driver)** — Windows WPF `.exe` со встроенным .NET и выбранные варианты SteamVR-драйвера в `xr-gate-windows-wsl-usbip.zip`. Драйвер включён в Windows-релиз.

Можно собирать обе платформы или только одну. При сборке только Windows установщик получает точный тег уже опубликованного Ubuntu-релиза с runtime и моделями, поэтому не требует повторной сборки Linux. Если такого релиза ещё нет, CI объяснит, что сначала нужно собрать и опубликовать Ubuntu. **Upload final artifacts to a GitHub Release** публикует только выбранные пакеты. При push/PR обычная проверка Ubuntu сохраняется.
